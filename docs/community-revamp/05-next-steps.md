## B. 需要先对齐（需汇报沉淀后决策）

> 原则：先统一方向，再大规模投入。

### B-01 搜索技术路线一期

- 决策点：先做论坛轻量搜索还是直接上全站统一搜索网关
- 供选项：
  - 选项 A：论坛轻量搜索（标题+标签）
  - 选项 B：全站统一搜索（资源+帖子+用户）
- 推荐选项：选项 A（先快后全）
- 决策人：产品负责人 + 后端负责人

### B-02 举报闭环策略

- 决策点：自动隐藏阈值与复核 SLA 如何设置
- 供选项：
  - 选项 A：阈值保守（3 人举报才隐藏）
  - 选项 B：阈值积极（2 人举报先折叠）
- 推荐选项：选项 A（降低误杀）
- 决策人：社区运营负责人 + 版主负责人

### B-03 信任等级规则

- 决策点：等级升级公式与降级规则是否同期开启
- 供选项：
  - 选项 A：先只升级不降级
  - 选项 B：升级与降级同时上线
- 推荐选项：选项 A（先建立正向激励）
- 决策人：产品负责人 + 社区治理负责人

### B-04 通知渠道优先级

- 决策点：邮件、实时推送、站内通知的上线顺序
- 供选项：
  - 选项 A：站内→邮件→实时
  - 选项 B：站内→实时→邮件
- 推荐选项：选项 A（实现成本和风控更稳）
- 决策人：产品负责人 + 后端负责人

### B-05 OAuth 与 token 策略

- 决策点：refresh token 存储与刷新策略
- 供选项：
  - 选项 A：短期沿用现方案 + 刷新接口
  - 选项 B：同步推进更严格 cookie 策略
- 推荐选项：选项 A（先修可用性）
- 决策人：架构负责人 + 安全负责人

### B-06 SSR 改造范围

- 决策点：首批 SSR 路由范围
- 供选项：
  - 选项 A：首页 + 论坛列表
  - 选项 B：首页 + 论坛列表 + 帖子详情
- 推荐选项：选项 A（先控风险）
- 决策人：前端负责人 + 性能负责人

### B-07 Follow/Feed 上线时机

- 决策点：是否在治理底盘稳定前上线社交扩张能力
- 供选项：
  - 选项 A：治理一期完成后再上
  - 选项 B：并行上线抢增长
- 推荐选项：选项 A（先控噪音）
- 决策人：产品负责人 + 运营负责人

### B-08 徽章体系节奏

- 决策点：徽章与信任等级是否同一版本上线
- 供选项：
  - 选项 A：先上线信任等级，再补徽章
  - 选项 B：两者同版上线
- 推荐选项：选项 A（避免规则复杂度叠加）
- 决策人：产品负责人 + 社区运营负责人
